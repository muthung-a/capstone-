# 프로젝트 규칙 (사람과 AI 코딩 도구 공통)

이 파일은 이 프로젝트를 고치는 모든 사람/AI가 따르는 사내 규칙입니다.
AI에게 일을 시킬 때는 **이 파일의 내용을 함께 보여주세요.** (데이터 파일은 절대 같이 주지 않습니다)

## 0. 절대 규칙 — 데이터 보안
- 병원 데이터(비식별 포함), 접수번호, 환자 관련 값은 생성형 AI·외부 서비스에 입력하지 않는다.
  AI에게는 컬럼 이름, 가짜로 바꾼 몇 줄, 오류 문구, 코드/설정 파일만 보여준다.
- 병원 파일은 프로그램 폴더 **밖**에 둔다. 폴더 안에 엑셀/CSV 가 있으면 `점검.bat` 이 실패하고, `.gitignore` 가 엑셀/CSV 를 git 에서 제외한다. (가상 샘플 `prototype/data/` 만 예외)
- 병원 데이터가 아닌 것으로 확인되기 전까지는 '파일이 실제 병원 데이터를 가공한 것'이라고 가정한다. 값/항목 이름이 보이는 화면 캡처도 외부 AI 에 보여주지 않는다.
- 데이터 파일(xlsx/csv)을 GitHub 등 저장소에 올리지 않는다. (이 폴더의 xlsx 3개는 모두 가상 데이터)
- 병원 파일의 구조를 AI 에게 설명해야 할 때는 `구조요약.bat` 결과(셀 값이 없음)만 사용한다. 파일 내용을 직접 복사해 붙이지 않는다.
- 프로그램은 이 PC 안에서만 접속되게 둔다: `.streamlit/config.toml` 의 `[server] address = "127.0.0.1"` 와 exe 런처의 `--server.address=127.0.0.1` 을 지우지 않는다.
- 외부 통신 코드 금지 (requests, urllib, socket 등). 화면 글꼴을 인터넷에서 받는 `USE_WEB_FONT` 는 False 로 둔다.
- 비밀번호·키·와이파이 정보를 코드나 문서에 적지 않는다.

### 구조 복제본에 관한 규칙
- 구조 복제본(`core/anonymize.py`)은 병원 파일에서 만든 '파생 자료'다. 외부(AI 포함)에 보여주기 전에 직접 열어 확인하고 병원/교수님의 허락을 받는다.
- 누출 검사는 **변환 코드와 독립적**이어야 한다. (원본의 이름 글자를 직접 모아 복제본과 대조. 변환이 고장 나도 기록이 없어 0건이 되면 안 된다)
- 파일 내부를 글자로 검사할 때는 XML 해석기로 푼다. openpyxl 은 한글을 `&#54861;` 같은 문자 참조로 저장하므로, 원시 바이트에서 한글을 찾는 검사는 아무것도 못 찾는다.

## 1. 구조와 경계 (도메인 경계)
```
config.py / stats_config.py   설정 (자주 고치는 곳)
core/      순수 계산·읽기·검증 — streamlit 을 import 하지 않는다
reports/   Excel / PDF 출력
ui/        화면 (core 를 부르는 방향만 허용, 반대 방향 금지)
app.py     조립만 한다
```
- 프로토타입 전용 기능(샘플 버튼, 배지, 가정한 통계, 샘플 기반 점검)은 `prototype/` 에만 둔다.
  본 코드는 `hooks.py` 로만 호출하고 `prototype` 을 직접 가져오지 않는다. (`prototype/` 을 지워도 돌아가야 한다)
- 새 통계: `stats_config.py` 와 `config.py`(배치) 만 수정한다. `core/`·`ui/` 는 새 '종류'(예: 새 차트 형태)가 필요할 때만 고친다.
- 차트는 `ui/charts.py` 의 `_show()` 한 곳으로만 화면에 내보낸다. (이미지 저장 설정 등이 모든 차트에 똑같이 적용되도록. 점검이 확인)
- `core/` 는 화면 라이브러리(streamlit)를 가져오지 않는다. (점검이 확인) 화면 코드는 `ui/` 에 둔다.
- 통계표 모드: 항목·기간 이름은 파일에서 온 글자이므로 화면 HTML 에는 항상 `esc()` 를 거친다. 새 차트는 `_show()` 로만 내보낸다.
- 화면의 각 영역은 `guard()` 로 감싼다. 한 영역의 실패가 화면 전체를 멈추게 하지 않는다.

## 2. 데이터 계약
- 프로그램 안에서 쓰는 컬럼 이름은 `config.COLUMNS` 에 정의된 것뿐이다. (자료형: text / number / month)
- 숫자는 쉼표·'원'을 제거해 숫자로, 년월은 `YYYY-MM` 으로 통일한다. (core/loader.py)
- 새 컬럼은 `COLUMNS` 에 한 줄 추가하고, 병원 엑셀의 이름은 `aliases` 에 넣는다.

## 3. 출력 안전 규칙 (실제로 사고가 났던 부분)
- 엑셀 값·파일 이름 같은 외부 글자를 화면 HTML 에 넣을 때는 `core.format.esc()` 또는
  `components.chip / warn_line / insight_list` 를 쓴다. f-string 으로 `unsafe_allow_html` 에 직접 넣지 않는다.
- PDF 의 `Paragraph` 에는 `xml_escape` 를 쓴다. Excel 은 `=` 로 시작하는 값이 수식으로 저장되지 않게 `_guard_formulas` 를 유지한다.
- `eval` / `exec` / `pickle` 금지. (pandas 의 `DataFrame.eval/query` 는 `stats_config.py` 에 개발자가 쓴 수식에만 사용)

- exe 배포: 앱에서 새 외부 라이브러리를 쓰면 `packaging/launcher.py` 의 import 목록에 추가한다. (점검이 확인)

## 4. 성능 규칙
- 행 단위 파이썬 루프(`iterrows`, `apply`)를 피하고 pandas 벡터 연산을 쓴다. 20만 행이 10초 안에 처리되어야 한다(점검 항목).
- 보고서(Excel/PDF)는 화면이 갱신될 때마다 만들지 않는다. (저장해 둔 것을 재사용, 행이 많으면 버튼으로 생성)

## 5. 변경 절차: 설계 → 구현 → 검증
1. **설계:** 고칠 파일, 영향 범위, 완료 조건을 먼저 적는다.
2. **구현:** 한 번에 한 가지 목적만. 점검을 통과시키려고 기존 예외 처리·방어 코드·점검 항목을 지우지 않는다.
3. **검증:** `점검.bat` 이 전부 `[OK]` 여야 한다. 새 통계/규칙을 추가하면 점검 항목도 함께 추가한다.
   화면(CSS)을 고칠 때는 Streamlit 버전이 달라도 '사이드바를 접었다 펼치기' 같은 기본 조작이 되는지 직접 확인한다. (상단 도구줄을 숨기다가 펼치기 버튼까지 지운 적이 있다)
   점검이 통과해도 화면에서 직접 확인한다. (점검이 못 보는 곳이 있다: 실제로 켜 보니 점검은 통과했는데 차트 1개가 안 그려진 적이 있다)
   점검이 실패하면 → 오류 문구를 AI 에게 주고 수정시킨 뒤 → 다시 점검한다. (자동 피드백 루프)
4. **보고:** "확인한 것"과 "확인하지 못한 것"(예: 실제 병원 데이터, 병원 PC 에서의 실행)을 나눠서 적는다.

## 6. AI 에게 일 시킬 때 템플릿
```
목표: (한 문장)
고쳐도 되는 파일: (예: stats_config.py, config.py)
건드리면 안 되는 것: AGENTS.md 의 0~4번 규칙, 기존 점검 항목
완료 조건: 점검.bat 전부 OK + (화면에서 확인할 것)
※ 데이터는 붙이지 않았습니다. 컬럼 이름: (적어주기)
```
